# Демо-сценарий: HSE podcast end-to-end

Цель — показать на одном корпусе, что R2 умеет от загрузки до сравнения
вариантов и MoE-ответа. Сценарий написан под живую демонстрацию и под
e2e-тест (см. `e2e/demo.spec.ts`).

## Предусловия

- backend на `http://localhost:8000` (см. `README.md`)
- frontend на `http://localhost:3001`
- backend.env: `DEEPSEEK__API_KEY=...` если хотим LLM-зависимые куски
  (llm_judge / chat); без ключа сценарий укорачивается до heuristic
- HSE podcast pre-loaded через миграцию или вызов API:
  `POST /api/corpora` + `/documents` + два билда `/graphs`
  (один с `ner_extraction + threshold_prune + leiden`, второй просто
  `ner_extraction`)

Имена вариантов в сценарии — `ner-leiden` и `ner-bare`.

## 1. Корпуса (Phase 6.5 + 6.1 design tokens)

1.1. Открываем `/corpora`.
1.2. Видим карточку **HSE Podcast** с двумя вариантами:
- `ner-leiden` — chip `ready`, builder `ner_extraction`, ~497 узлов
- `ner-bare` — chip `ready`, ~459 узлов

**Что проверяем UX-wise:** карточный layout, status chips, hover-тень,
кнопка `+ Новый корпус` справа сверху ведёт в `/wizards/build`.

## 2. LayeredGraph + хоткеи (Phase 6.6.1)

2.1. Кликаем `ner-leiden` → `/graphs/{id}`.
2.2. В шапке: имя варианта, builder/cleaners/clusterer, метрики
(узлов / рёбер / версия), кнопки *Показать Suggestions* и *Экспорт
журнала*.
2.3. Снизу — toolbar `Layer: chunk entity community topic all layer-map`
+ подсказка по хоткеям.
2.4. Жмём `2` → активным становится `entity`-слой; chunk и community
становятся полупрозрачными (alpha 0.2).
2.5. Жмём `Tab` → переключение на следующий слой по циклу.
2.6. `0` или `Esc` → возврат к показу всего.

**Что проверяем:** opacity-focus в 2D-layout (без 3D), хоткеи, плавные
переходы.

## 3. Layer Map overlay (Phase 6.6.2)

3.1. Жмём `L` → выезжает overlay с заголовком `Layer Map`.
3.2. В списке — все 4 слоя со swatch-точками, рукояткой `⋮⋮`, slider'ом
α и кнопкой `focus`.
3.3. Перетаскиваем `entity` ниже `chunk` → меняется визуальный Z-stack
(но семантическая иерархия в данных не двигается).
3.4. Двигаем α `community` → 0.5 → точки общин блекнут плавно.
3.5. Включаем `Slice` → видим только активный слой.
3.6. Жмём `Сбросить` → всё назад к дефолтам.
3.7. Закрываем overlay (`L` или `Esc`).

## 4. NodeDrawer + Tools-on-nodes (Phase 6.9 / Phase 5)

4.1. Кликаем на любой entity-узел (например, "ВШЭ" или "Иванов").
4.2. Справа выезжает NodeDrawer: имя, layer-chip, type-chip, summary
(если есть), список применимых tools.
4.3. Нажимаем `show_neighbors` → JSON-результат появляется внизу: список
соседей по edge type, общее число.
4.4. Если узел `PERSON`/`ORG`/`PLACE` — нажимаем `corpus_collocations`
→ результат: топ-K сущностей, со-упомянутых в тех же чанках.
4.5. История инвокаций под результатом — две записи.
4.6. Жмём `×` → drawer закрывается.

## 5. Suggestions sidebar (Phase 3.5 / 3.6)

5.1. Жмём в шапке *Показать Suggestions* → слева выезжает sidebar.
5.2. Видим заголовок + chip-strip *Запустить агента*.
5.3. Жмём `low_confidence_triplet` → через секунду в списке появляются
DELETE-предложения с rationale (`weight 0.X < 0.30`).
5.4. На первой карточке — *Accept* → она исчезает, метрики варианта в
шапке обновляются (version v0 → v1, узлов/рёбер пересчиталось).
5.5. На следующей — *Reject* → карточка тоже уходит, но версия
варианта не меняется.
5.6. Кликаем *Экспорт журнала (JSON)* в шапке → скачивается JSON с
журналом курации (одна запись DELETE_EDGE).

## 6. Split-view MoE compare (Phase 6.8)

6.1. Открываем `/graphs/compare?ids={ner-leiden},{ner-bare}`.
6.2. Видим две панели рядом, заголовок каждой — имя варианта + метрики.
6.3. Жмём `2` → **обе** панели одновременно фокусируются на entity-слое.
6.4. В одной панели кликаем по узлу (например, "Москва"), который
есть в обоих вариантах с одинаковым `canonical_id`.
6.5. На правой панели подсвечивается соответствующий узел (selection
синхронизирован по canonical_id).

## 7. Ask wizard + MoE SSE (Phase 6.4 / Phase 4)

7.1. Открываем `/wizards/ask`.
7.2. Шаг 1 — выбираем `Mixture of Experts` → клик `Далее`.
7.3. Шаг 2 — отмечаем оба варианта (`ner-leiden`, `ner-bare`) → `Далее`.
7.4. Шаг 3 — выбираем reasoner `keyword_search`, aggregator
`evidence_union` → `Далее`.
7.5. Шаг 4 — вписываем вопрос *"Кто работает в ВШЭ?"* → `Далее`.
7.6. Шаг 5 — жмём `Спросить`. Видим:
- Появляются карточки *Эксперты* — по одной на вариант, через SSE-поток
- Каждая показывает reasoner-имя, variant-id (короткий), confidence,
  текст ответа, число evidence-узлов
- В конце — финальный блок *Финальный ответ* с aggregator-trace и
  metadata (cost / confidence / evidence)
- CTA *Открыть сравнение вариантов* (если режим MoE) — ведёт на 6.

7.7. Жмём *Перезапросить* — стрим повторяется.
7.8. Жмём *Остановить* во время потока — выполнение прерывается.

## 8. Чат-affordance (Phase 6.4 — UI готов, LLM endpoint TODO)

На любом шаге визарда — кнопка `💬 спросить ассистента` справа сверху.
Жмём — открывается боковой чат с заглушкой ("чат-помощник пока не
подключён к LLM"). UX-проверка: панель открывается/закрывается, контекст
шага показан.

## Что не покрывает

- Build wizard (`/wizards/build`) — отдельный e2e (создание корпуса,
  загрузка документов, EDA-recommendation, выбор pipeline, build).
- AskAssistant с реальным LLM — backend-endpoint в roadmap.
- GAT ranker training (требует команду из терминала, не UX-щенький).

## Минимальный smoke (CI-friendly)

- `/corpora` загрузился, видна карточка `HSE Podcast`
- `/graphs/{id}` загрузился, видна метрика *Узлов* > 0
- Хоткей `2` фокусирует entity-chip
- `/wizards/ask` шаги проходят до конца, SSE приходит, финальный ответ
  не пустой
