## 0. Единая визуальная грамматика дельты (ядро вклада)

Один и тот же encoding для всех трёх осей — это и есть «грамматика», которую мы
заявляем как контрибуцию (а не «ещё одна раскладка»):

| Состояние узла/ребра | Кодировка |
|---|---|
| появилось (born) | заливка зелёным, fade-in |
| исчезло / инвалидировано (dead) | приглушённое + перечёркнутое, fade-out |
| сохранилось (persisted) | нейтральный цвет |
| сменило community (moved) | подсветка контура + «лифт» к новой общине |
| в evidence текущего ответа (query) | непрозрачно, остальное alpha 0.15–0.25 |

Переключатель оси (time / edit / query) меняет *источник* дельты, но не язык. Это даёт
рецензенту мгновенно читаемую картинку «что и почему изменилось» — ровно то, чего не
было в 205.

## 1. Backend-предпосылки (минимальные, без новых сервисов — см. feedback_minimal_stack)

- **1.1. Bi-temporal поля** на `Node`/`Edge` (Pydantic + миграция):
  `valid_from`/`valid_to` (event time T) и `tx_from`/`tx_to` (transaction/ingestion
  time T′). Заявляем визуально, а не для recall (см. ADR 0002).
- **1.2. `IngestionEvent` / `Snapshot`** — единица временной оси: окно сборки
  (для подкаста — дата эпизода; для новостей — дата публикации). Граф в момент `t` =
  факты с `tx_from ≤ t < tx_to` (и/или `valid_*` для event-time режима).
- **1.3. `temporal_diff(t_a, t_b) -> {born, dead, persisted, moved_community,
  invalidated}`** — переиспользует механику `affected_set` (Phase 2), но по временной
  оси. Возвращает per-node/edge дельту для грамматики §0.
- **1.4. Invalidation-provenance**: какое ingestion-событие/экстракция привело к
  инвалидации ребра (нужно человеку, чтобы откатить неверную авто-инвалидацию —
  диагностический угол из ADR 0002).
- **1.5. Latency-инструментовка**: backend возвращает фактическое время recompute на
  каждую правку (нужно показать в UI и в paper — прямой запрос R3).

## 2. Frontend-компоненты

### 2.1. Timeline scrubber (HEADLINE, закрывает «нет EDA-новизны»)
- Горизонтальная ось эпизодов/дат снизу графа; ползунок + play.
- Скраб → граф морфится в состояние на момент `t`; в diff-режиме подсвечивает
  born/dead/moved по грамматике §0.
- Тумблер **event-time (T) ↔ transaction-time (T′)** — принципиальный угол против
  XGraphRAG/Graphiti (ADR 0002).
- Темпоральное окно **само сжимает видимый граф** → ответ R1 «граф огромный, нечитаемый».

### 2.2. Query-delta (закрывает главную претензию R1 — фича была невидима)
- Задаёшь вопрос → evidence-подграф ответа загорается, остальное гаснет.
- Явно показываем дельту против полного графа («вот что использовано, вот что нет»).
- Это та самая «query-dependent change», которую R1 не увидел в демо.

### 2.3. Edit-delta / каскад (закрывает «самое интересное» по R3 + дифференциатор)
- После merge/split/retype — анимация распространения `affected_set` наружу по слоям.
- Before/after слайдер; показываем переформирование community и какие QA-ответы
  изменились бы.
- **Badge с latency recompute** на каждой правке (R3: «report latency numbers» +
  держит интерактивный flow, без dead air).

### 2.4. Invalidation-curation панель (диагностический угол / отстройка от Graphiti)
- Список авто-инвалидированных фактов с provenance (когда/почему/каким событием).
- Кнопки accept / **revert** неверной инвалидации → пишется в curation journal (Phase 2).

### 2.5. Стабильность и error-feedback (закрывает R2)
- Если merge ломает запрос — явный error/empty-state с объяснением «что произошло и
  что сделать», вместо тихого падения (R2 жаловался ровно на это).

### 2.6. Guided walkthrough (закрывает R1 «нет объяснения как пользоваться»)
- Онбординг-оверлей, сценарно совпадающий с `demo_scenario.md`; шаги пронумерованы.
- Хореографированный demo-путь (R3: «tightly choreographed to avoid dead air»).

### 2.7. Сохраняем обязательные UX-свойства (feedback_wizard_backnav)
- Чат-affordance и свободная back-навигация в визардах — не ломаем при добавлении
  временной оси.
